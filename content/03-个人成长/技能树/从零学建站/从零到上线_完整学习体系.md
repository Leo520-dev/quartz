# 第一卷 · 核心概念（零基础看懂）

> 目标：看完后你能说清楚"网站是怎么工作的"，理解AI在做什么。

## 1.1 网站到底是什么——拆开给你看

一个网站 = **三个东西**：

```
浏览器里看到的（前端）      ← 就是页面长什么样、按钮在哪、动画怎么动
         ↕ 通过网络通信
服务端算好的数据（后端）    ← 用户登录验证、算价格、存数据库
         ↕ 读写
数据库里存的内容（数据库）  ← 产品列表、Installer账号、报价记录
```

**现实类比：一家餐厅**

| 网站术语 | 餐厅类比 | 你的网站 |
|---------|---------|---------|
| **前端** | 餐厅的门面、菜单、装修 | MOOVED官网页面、产品展示、Installer工作台界面 |
| **后端** | 厨房和后厨系统 | 用户登录验证、计算报价、生成PDF |
| **数据库** | 仓库（存放食材/订单记录） | 产品信息、Installer账号、报价记录 |
| **服务器** | 餐厅本身（租的场地） | Vercel（免费帮你跑程序的地方） |
| **域名** | 餐厅地址 | moovedsolar.com |

**你每天的工作流：**

```
你告诉AI你想要什么 → AI写出代码 → 你把代码存到电脑里 → 在浏览器看效果
                                                          ↕ 不满意就截图告诉AI改
效果满意 → 部署上线 → 全世界都能访问了
```

## 1.2 前端 vs 后端——你各需要懂多少

| | 前端 | 后端 |
|---|------|------|
| **通俗说** | "页面长什么样" | "背后怎么算" |
| **你的网站里** | 官网首页、产品页、Installer工作台界面 | 登录验证、报价计算、PDF生成 |
| **AI能帮你做** | ⭐⭐⭐⭐⭐ 几乎全部 | ⭐⭐⭐⭐ 大部分 |
| **你需要理解** | 浏览器怎么显示页面、怎么和AI说"这里改一下" | API是什么、数据存在哪 |
| **完全不需理解** | CSS动画原理、JavaScript闭包 | 服务器负载均衡、数据库索引优化 |

> **关键认知**：你不需要学会"写"代码，你要学会的是"看懂并修改"AI写的代码。

## 1.4 域名/DNS/服务器——你的网站怎么被访问

```
用户打开浏览器 → 输入 moovedsolar.com
         ↓

         ↓
请求到达Vercel的服务器 → 服务器把网页数据发回给用户
         ↓
用户浏览器渲染出你的MOOVED官网
```

**你需要做的：**
1. 买域名（Namesilo/GoDaddy/Aliyun 约¥60-80/年）
2. 把域名指向Vercel（让AI教你，10分钟）
3. 完事

## 1.5 API是什么——两句话讲明白

**API = 一个"中间人"，让不同软件能互相说话。**

```
你的网站（前端） → [通过API说"我要登录"] → Supabase（数据库）
你的网站（前端） → [通过API说"算个价格"] → 后端计算出结果返回
```

你写代码时，AI会不断提到"调API"这个词。你只需要知道：**API就是软件之间打招呼的方式**，就像你打电话说"喂"一样自然。

## 1.6 AI的能力边界——它行它不行

### ✅ AI擅长的

| 能力 | 评级 | 说明 |
|------|------|------|
| 生成代码 | ⭐⭐⭐⭐⭐ | 你要什么页面，它直接给你完整的代码 |
| 改样式 | ⭐⭐⭐⭐⭐ | "把按钮改成蓝色+圆角" → 立刻改好 |
| Debug | ⭐⭐⭐⭐⭐ | 报错信息复制给AI → 告诉你哪行错了怎么改 |
| 解释概念 | ⭐⭐⭐⭐ | "什么是API？用餐厅打比方" → 讲得很清楚 |
| 从截图生成代码 | ⭐⭐⭐⭐ | 你看到喜欢的页面→截图→"帮我做成这样的" |
| 整合多个功能 | ⭐⭐⭐ | "把登录和报价整合到一起" → 基本可以 |

### ⚠️ AI不擅长的（你要注意）

| 短板 | 说明 | 你的对策 |
|------|------|---------|
| **上下文遗忘** | 聊久了会忘记前面说过什么 | 重要的事情每轮都提一次 |
| **生造不存在的东西** | 会编造不存在的库/函数 | 如果AI给了奇怪的东西，让它"给我一个不需要额外安装的方案" |
| **一次生成完美代码** | 第一次往往有小bug | 接受迭代：第一版→发现问题→让AI修→再看效果 |
| **大文件/长代码** | 代码太长它会漏掉中间部分 | 拆成小模块，一次做一个功能 |
| **安全性** | 不会主动考虑黑客攻击 | 涉及到用户密码、支付时，让AI加上"基本安全措施" |

# 第二卷 · 和AI协作的艺术

> 目标：学会高效使用AI写代码，以及AI写错了如何纠正它。

## 2.1 5条黄金提问法则

### 法则1：给足上下文

```
❌ 差："帮我做一个产品页面"
✅ 好："帮我做一个MOOVED太阳能产品的展示页面，展示3款逆变器，
    每款有：产品图片、型号、功率、价格。用卡片布局，一行3列。
    风格是明亮科技风，白色背景+蓝色主色调。用Next.js + Tailwind CSS。"
```

### 法则2：一次只做一个功能

```
❌ 差："做一个完整的官网，包括首页、产品页、登录、报价"
✅ 好：先做首页 → 验收 → 再做产品页 → 验收 → 再做登录 → 验收

一次说太多，AI会遗忘中间的需求。
```

### 法则3：截图+描述=最高效

```
遇到问题时：
  "这个页面（贴截图），右上角的按钮位置偏下了，
  我想让它和左侧的标题对齐。"
  
比写一百字描述都管用。
```

### 法则4：迭代，而不是期望一次性完美

```
Round 1: "用Next.js+Tailwind生成MOOVED官网首页"
  → 看到页面
Round 2: "Logo太大了，缩小一半，移到左上角"
  → 调整
Round 3: "背景改成浅灰白色，导航栏改成透明"
  → 再调整
...
Round 8: 效果满意
```

**预期：每个页面平均需要3-5轮迭代才能满意。**

### 法则5：遇到报错=先复制再问

```
当终端出现红色报错时：
  1. 选中所有报错文字 → Ctrl+C
  2. 发给AI + "这个报错是什么意思？怎么修复？"
  3. AI告诉你哪行错了 → 按它说的改
```

## 2.2 AI写错了怎么办（3种纠错方法）

### 方法1：重新说清楚

```
AI给了你不想要的东西时：
  → "不对，我说的是...重新生成"
  → "不是这个意思，我重新描述一下..."
```

### 方法2：截图+指向

```
"截图（红色圈出问题区域），这里不对，应该是..."
```

### 方法3：怀疑AI生造时

```
如果AI给了你一个看起来不存在的库/功能：
  → "这个库/功能真的存在吗？给我一个不需要额外安装的方案"
  → "用更基础的方式实现，用原生API，不要用第三方库"
```

## 2.3 常见AI翻车场景+应对

| 场景 | 表现 | 应对 |
|------|------|------|
| AI生造不存在的函数 | "用xxx库实现"但库不存在 | "用原生方法替代，不要用第三方库" |
| 跑完报错 | 复制报错给AI它说"哦我改一下" | 正常，让AI修就行 |
| AI给了一大段代码但漏了关键部分 | 运行报缺少某文件 | "你刚才漏掉了配置文件，再生成一下" |
| AI前后矛盾 | 之前说A方案，后面说B方案 | "刚才你不是说用A方案吗？保持一致" |
| 页面和想要的不一样 | 布局/颜色/内容都跑偏了 | 截图+重新描述需求，不要接受 |

mooved-website/

## 4.5 加纳市场特别注意事项

| 注意点 | 说明 |
|-------|------|
| **移动端优先** | 加纳用户很多只用手机上网，每个页面都要让AI适配手机 |
| **加载速度** | 加纳网络不太稳定，让AI优化加载速度（图片压缩、代码精简） |
| **货币显示** | 涉及价格的地方显示 GHS（₵）和 USD 双币种 |
| **电话号码** | 加纳号码格式 +233 XX XXX XXXX |
| **WhatsApp链接** | 每个页面留一个"WhatsApp咨询"按钮 |
| **内容翻译** | AI可以帮你翻译，但找当地人校对一遍再上线 |

## 4.6 遇到困难时的处理流程

```
遇到困难了
    ↓
是安装环境的问题？
    ├─ 是 → 复制错误给AI → "这个怎么解决"
    └─ 不是 ↓
是AI生成的代码跑不起来？
    ├─ 复制报错给AI → "修复这个bug"
    └─ 如果AI修了3次还不行 ↓
换个方式问AI
    ├─ "换一种实现方式"
    └─ "用更简单的方法，不用任何第三方库"
        ↓
如果还不行 → 跳过这个问题，先做其他功能
    等后面知识多了再回来处理，或者我来帮你
```
